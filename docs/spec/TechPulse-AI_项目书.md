> **立项评审版 · 2026-10-27 · v1.0（依据已保存研究报告重建）**

## 0. 阅读说明与证据边界

用户提供的《deep-research-report (5).md》是 Deep Research 的**研究摘要**，而非原先声称已生成的四份附件正文。本项目书以该摘要中的选题、架构、指标、技术路线和预算作为**已提供研究结论**，并补入立项所必需的客户画像、商业假设、决策标准和财务情景。这些补入部分属于**待验证的规划**；未声称复原原始附件的逐字内容。

摘要里的 `turnXXsearchY` 一类引用属于原研究会话内部标记，无法在本文件中独立追溯。本文在末尾给出官方资料入口作为核验清单；涉及价格、API 配额、许可、法规的事实，**必须在上线前以当日官方内容复核**。财务数字是计算示例，不是市场预测或供应商正式报价。

## 1. 执行摘要

TechPulse-AI 是由 Grokbot 调度多个 AI Agents 完成的数字化技术情报生产线：从 OpenAlex、Crossref、arXiv、GitHub、Hacker News、合规 RSS 和企业公开披露采集机器可读信号；经数据源许可检查、原始归档、标准化、PII 清理、去重、实体解析、混合检索、主题聚类、时间窗趋势评分、反证搜索与事实核验，自动生成日报、周报、技术专题档案、Dashboard 和只读 API。**每项重要结论都必须有原始 URL、证据摘录、发布时间与采集时间，拒绝无证据的高置信判断。**

全项目不采购硬件、不操作物理设施、不需要线下交付；开发、测试、部署、在线内容生产、质量审查与监控均可委派 Agent。不可完全消除的人工动作仅限用户授权/开户注册、密钥配置、付款与预算审批、法律条款确认、对外服务发布和经营决策。项目禁止金融交易、自动发帖刷量、垃圾邮件、绕过登录墙或验证码、未经授权的网页抓取与内容再分发。

**决策建议：** 第 1 周先建立可追溯数据与安全边界，第 2–4 周完成核心流水线，第 5–6 周完成评估、发布与自动化验收。用 30 天核验内容质量与至少 15 次目标客户访谈，用 90 天实付客户/运营成本决定扩张或停止。

## 2. 立项目标与成功定义

### 2.1 北极星目标

让技术经理在 10 分钟内通过**可复核的证据包**理解一个技术主题最近 7/28 天发生的变化、为何值得关注、有哪些反证、以及该结论的置信度，而非让模型凭印象生成趋势文章。

### 2.2 MVP 范围

| 维度 | MVP 要求 | 暂不包括 |
|---|---|---|
| 数据来源 | 学术三源、GitHub、HN 共至少 5 类已审核连接器 | 未公开接口、付费墙全文、未经许可的商业数据库 |
| 信息处理 | 归档、清洗、许可证标记、PII 过滤、去重、实体合并 | 全网无限爬取、非授权全文抓取 |
| 分析 | 7/28 天信号、主题聚类、可解释评分、反证检索 | 无法解释的端到端“神谕式”分数 |
| 内容输出 | 中文周报、专题证据卡、Markdown 导出 | 无人工授权的第三方平台自动投稿 |
| 服务 | 只读 API、Web Dashboard、访问日志 | 未经批准的对外收费/支付操作 |
| 运维 | 限流、预算熔断、CI、自动化 QA、告警、备份 | 自动扩权、自动开通云付费资源 |

### 2.3 机器验收门槛（研究摘要提供）

| 量化指标 | 发布门槛 | 主要测法 |
|---|---:|---|
| 正文抽取成功率 | ≥97% | 按合法且可读取样本统计 |
| 必填字段完整率 | ≥98% | Pydantic / SQL 非空约束 |
| 去重 Precision / Recall | ≥0.98 / ≥0.95 | 有人工标注的冻结金标准集 |
| 检索 nDCG@10 | ≥0.75 | 多语种相关性金标准 |
| 检索 Recall@20 | ≥0.85 | 多源召回评估 |
| 事实 Claim 的引用覆盖 | ≥95% | 自动抽取 Claim 与证据配对 |
| URL 可追溯率 | 100% | 记录有效 URL、采集快照和 hash |
| 数值/日期一致性 | ≥98% | 结构化事实对照 |
| 高置信趋势来源族 | ≥3 | 源类别去重计数 |
| 高置信 Tier-A 证据 | ≥2 条 | 证据分级规则校验 |
| 提示注入红队样例 | ≥100 | 测试 fixtures |
| 未授权工具调用、密钥泄漏和越权外联 | 0 | 审计和红队检查 |
| 24 小时无人值守 P0 成功率 | ≥99% | 调度、重试及完成状态统计 |

上述门槛是**目标**，不是目前产品已达到的实测结果。任何质量不足的报告不得强行发布。

## 3. 客户、场景与需求假设

### 3.1 目标客户

| 角色 | 工作目标 | 现行替代方案 | 产品价值主张 | 关键验证 |
|---|---|---|---|---|
| AI 软件团队 CTO/Tech Lead | 快速判断技术路线与框架成熟度 | 阅读论文、GitHub、newsletter | 跨源一致性+可点击的反证 | 每周是否持续使用 |
| 企业创新/战略团队 | 识别中短期技术机会 | 咨询报告、内部简报 | 透明时间序列+更新原因 | 是否有预算持有人 |
| 研发/架构师 | 跟踪依赖生态和研究动向 | GitHub releases / arXiv 订阅 | 论文、仓库、事件之间的实体关联 | 是否减少手工跟踪时间 |
| 科技分析师或行业媒体 | 快速制作可引用研究资料 | 搜索引擎、通用 LLM | 证据包、结构化引用与 QA | 愿为可靠性付费否 |

目标客户和使用场景由项目设计推断；保存报告中未包含用户访谈原始记录、实际付费订单或可用 TAM/SAM 数据，因此不能宣称“市场需求已验证”。

### 3.2 核心需求假设

1. 用户需要**持续更新**而不是一次性搜索结果。
2. 用户愿为**可复核的证据和反证**支付额外费用。
3. 用户需要**跨源关系**（论文 → 开源仓库 → 企业披露/社区讨论）而非单源提醒。
4. 用户能接受“没有足够证据，因此不发布高置信结论”的审慎输出。
5. 客户对 API、可配置主题和历史序列的支付意愿高于泛化日报。

验证方式是定向访谈、真实试点、样报留存及最终付费转化，而不是让 Agent 对市场需求进行主观评分。

## 5. 产品形态与用户体验

### 5.1 首页 / 趋势榜

默认显示关注主题 7d/28d 趋势榜；每条卡片含主题、趋势分数、置信区间/级别、变化幅度、独立来源族数量、最近证据时间、关键反证数。默认排序是趋势分数 × 置信校准，不以单日社交热度排首位。

### 5.2 趋势详情页

显示时间序列、信号分类、Top 证据卡、反证卡、相关 GitHub 仓库/论文/企业事件；每个证据卡可打开原始网址，并列出快照时间、内容许可标签、提取长度和引用范围。证据缺失时用明确的“未证实”占位，不编造链接。

### 5.3 周报与导出

默认每周生成：本周新增、显著变化、证据最强趋势、可能的假阳性与待观察信号。每个重要结论附来源。首版只导出 Markdown 和 JSON；DOCX/PDF 为后续按需转换，不能使用第三方受版权保护的全文再分发。

### 5.4 配置与运营台

仅管理员可编辑主题、合规白名单、抓取预算与模型路由。数据源被冻结时显示明确原因（403、429、政策阻断、质量不达标），不做“自动修复绕过”。

## 6. 业务模型与竞争差异化

通用搜索工具回答临时问题，论文/仓库订阅工具只提供单源更新，商业情报产品通常具有更成熟的客户网络或专有数据。TechPulse-AI 不应宣称“没有竞争对手”，而应定位为**公开技术证据的机器可追溯、可复现、持续更新的轻量情报层**。

可积累的差异化：高质量公开来源适配器与政策记录、实体图谱、长期趋势序列、多语种检索评测集、Claim-Evidence 审计链、客户可配置主题与稳定 API。仅仅“用了多 Agent”不是护城河。

### 6.1 收费假设

- 免费样报与有限查询，促进用户体验，而非免费提供无限全文数据库。
- 专业订阅按主题数、更新频率、历史窗口、API 使用量和协作席位分层。
- 企业版提供专属保留策略、可审计部署和定制行业词典，但须单独核算服务成本与合同责任。
- 任何收费、发票、税务、Stripe/支付账户均需获用户授权；Agent 只生成配置与待审批清单，不代做 KYC 或资金操作。

建议测试的月价锚点：$99（小团队）、$199（专业团队）、$299（高级团队）；**这些只是实验定价，不是调研所得市场成交价**。

### 6.2 获客验证

第 7 天以前产出两份样报并记录可复核证据；30 天内完成至少 15 次结构化访谈，记录目标、替代工具、当前预算、采购责任、测试使用情况。通过允许的自有网站、许可的社区分享或已建立关系的个人邀请开展试点；禁止购买邮件名单、海量冷邮、批量私信、伪造账号或机器人刷量。以**真实付费试点**而非点赞量评估需求。

## 7. 技术方案与系统边界

### 7.1 逻辑架构

```text
官方公开 API / 合规 RSS / 公司 IR
            ↓
访问政策核验 + Collector Agent（外部只读）
            ↓
Raw Object Storage（原文/元数据在许可范围内）+ SHA256 + Provenance
            ↓
Cleaner（格式、PII、版权、许可）→ 去重 → 实体解析
            ↓
PostgreSQL（主记录）+ pgvector（MVP）/ Qdrant（扩展时）
            ↓
Dense/BM25 混合召回 → Reranker → 主题聚类
            ↓
7d/28d 特征 → 趋势分数 → 证据检索/反证检索
            ↓
Writer 生成草稿 → 独立 QA → 发布门禁
            ↓
只读 API / Web Dashboard / Markdown 周报
```

### 7.2 默认组件

Python/FastAPI、PostgreSQL + pgvector、对象存储、可审计结构化日志、Docker、GitHub Actions；可靠工作流首选 Temporal，单个复杂 Agent 的状态控制可选 LangGraph。低规模 MVP 可用 Postgres 全文检索配合向量检索，**只有当基准测试或容量指标触发时才增加 Qdrant**。具体包版本与云价格必须运行 P00 的兼容性检查后写入 lockfile，不虚构已经可用的服务实例。

### 7.3 数据与检索

OpenAlex、Crossref、arXiv 构成研究元数据主干；GitHub 构成代码活动证据；HN/RSS 构成开发者关注补充；SEC/公司 IR/中国交易所公告为后续可启用的数据源。系统从许可与访问条款开始设计：遇到验证码、权限拒绝或 robots 不允许必须阻断，不依赖内部隐藏接口。

检索采用 Dense Top-100 + BM25/Sparse Top-100 → RRF Top-50 → reranker Top-10，按多语种金标准集评估。模型微调仅在满足**≥10,000 个 query-document 训练对、基础模型 nDCG@10 < 0.75、GPU 与预算均具备**时作为条件实验；默认禁止在 MVP 阶段微调。

### 7.4 可信与权限

网页/论文/仓库文本均属于数据，不得升级为指令；Collector 只能外部 GET + 内部 Raw PUT，Cleaner 无外网，Writer 只能读 sanitized evidence，DeployAgent 仅操作获批的自有环境，生产密钥与模型上下文隔离。敏感个人数据在 Embedding 前移除或不可逆处理；保留 `source → canonical → chunk → vector → report` 删除链。任何工具越权、密钥泄漏、无证据高置信报告都属于阻断发布事件。

## 8. 成本、收入与单位经济

报告提供的常态运行规划目标是 **$300–1,000/月**（不是供应商报价）；示例容量为日增约 10,000 条、80% 确定性或本地处理、最多 20% LLM 深处理、日约 500 条高价值候选进入高阶综合。默认每日 LLM 硬上限 **$25**，80% 时降级，100% 时停止非 P0 任务。发布前需重新抓取官方模型/云价格并生成定价快照。

下表是用于讨论的**数学情景，不是预测**：

| 指标 | 保守 | 基准 | 积极 |
|---|---:|---:|---:|
| 付费客户（假设） | 3 | 20 | 60 |
| 客户月均收入（假设） | $99 | $199 | $299 |
| MRR = 客户 × ARPA | $297 | $3,980 | $17,940 |
| 云/模型/存储 | $300 | $650 | $1,000 |
| 支付、支持等可变成本 | $50 | $200 | $500 |
| 简化月度贡献额 | **-$53** | **$3,130** | **$16,440** |

不包含固定研发人力、税费、销售获客费用、退款、法律咨询、商业数据授权及可能的规模扩容。因此不得作为净利润、回本周期或估值结论。以基准运维与可变成本 $850/月、ARPA $199/月作简单测算，约需 5 个客户才可覆盖上述**有限费用口径**；完整盈亏平衡点会更高。

## 9. 路线图、预算门禁与 Go/No-Go

| 时间点 | 交付 | 必须满足 |
|---|---|---|
| 48 小时 | 范围冻结、源政策注册表、工程仓库、Schema、基础样本 | 不存在必须绕过访问控制的依赖 |
| 7 天 | 最少 3 个源可端到端落库，归档、CI、静态样报 | 原始证据可回放，无密钥泄漏 |
| 30 天 | 5 源、主题趋势、反证、QA、API/周报，≥15 次访谈 | QA 核心门槛与 ≥3 个试点付费意向 |
| 90 天 | 自动运维、稳定报告、首批付费试点、成本复盘 | ≥5 个实际付费客户，或明确有证据的转型决定 |

**GO：** 许可可核验，核心流水线可回放，URL 可追溯率 100%，事实门禁通过，费用受控，客户存在实付或明确试点意愿。

**CONDITIONAL GO：** 技术质量达标但没有付费验证；暂停扩容，只保留样报与客户发现。

**NO-GO：** 商业可行性必须依赖不合规抓取、未经授权的全文分发、无法限制推理费用、持续虚假引用、或 90 天内缺乏合理付费路径。

## 10. 风险登记

| 风险 | 监控信号 | 控制 | 默认处置 |
|---|---|---|---|
| API/ToS 改变 | 403、429、验证码、条款更新 | Policy Registry、限速 | 冻结该源，审查后再启用 |
| 事实幻觉 | Claim 无 URL 或无法对照 | Evidence QA、反证搜索 | 报告不发布，局部重跑 |
| 提示注入 | 外部文本索要执行命令/密钥 | 指令/数据隔离、工具白名单 | 隔离样本，加入红队集 |
| 版权与隐私 | 原文再分发、PII 入索引 | 许可过滤、PII 清洗、删除映射 | 停止发布，删除与重建索引 |
| 成本失控 | Token 激增、任务循环 | 预算器、重试上限、熔断 | 停止非 P0 任务 |
| 低付费转化 | 免费阅读无复购 | 付费试点、定价实验 | 重新定位 ICP/价值 |
| 模型/云锁定 | 不兼容迁移 | 开放格式与封装适配器 | 按离线基准切换组件 |
